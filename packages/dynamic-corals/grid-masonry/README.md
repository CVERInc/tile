# grid-masonry

sitetile's `%% sitetile: grid pack=masonry %%` layout. The renderer (`packages/emit/grid.mjs`)
writes every card as one flat sequence plus the mount point on the cards' container; this coral
regroups the cards into `cols` column boxes by DOM-order parity (card `i` → column `i % cols`) at
the theme's breakpoints, re-running on resize and `astro:page-load`. It measures nothing, so it is
correct the moment the DOM exists. Below the first breakpoint, and without JS, the cards stay one
flat sequence. See the header of `grid-masonry-client.mjs` for why parity, not height.

Only VISIBLE cards are bucketed: a card a `filter=` pill hid (`grid-filter`, which sets `hidden`)
stays in the container after the columns, and `i` counts the visible cards. The layout re-runs
when `grid-filter` sends `dc-grid-filter-change` to the container, so a filtered set fills the
columns from the top.

Local-only (no registry channel): sitetile's `Grid.astro` imports the client source and Astro
bundles it into the page; `grid-masonry.js` is the built artifact for a host that serves corals itself.

## grid-masonry metadata

Packs a grid's cards into column boxes by DOM-order parity at the theme's breakpoints.

Author: `official`.

Host: `sitetile`. Renderer output, not a standalone copy-paste embed. The renderer emits the mount point and the section's markup; sitetile's section component imports the client source and Astro bundles it into the page, and a Worker host serves the built artifact itself. The breakpoints in the client must match the theme's `.st-cells[data-pack="masonry"]` CSS, which the renderer's `data-pack` attribute selects.

### Embed

```html
<div class="st-cells" data-dynamic-coral="grid-masonry"><div class="st-cell">One</div><div class="st-cell">Two</div><div class="st-cell">Three</div></div>
<script src="grid-masonry.js"></script>
```

### Attributes

| Attribute | Type | Required | Default | Purpose |
|---|---|---|---|---|
