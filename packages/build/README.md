# @tile/build — the page-generation half of a site build

An IR directory in, a directory of plain static HTML out.

This package is the machinery that turns a site's markdown IR into pages: collect the IR into the
`site_pages` shape, stage it into the renderer (`packages/sitetile/astro`), run `astro build`, put
the renderer back. That is the whole of how a page is produced, and it is here, in public, under
MIT, because a site you can export but not rebuild is not a site you own.

## The three-line rebuild

```
git clone https://github.com/CVERInc/tile.git engine
(cd engine/packages/sitetile/astro && npm install)
node engine/packages/build/cli.mjs ./ir ./dist --site-url https://your-domain.example
```

`./ir` is the site's exported IR directory — `home.md`, `_site.md`, `legal/terms.md`, `zh-tw/…`,
`posts/…`. `./dist` is the result: static HTML. Serve it with anything.

Pass `--theme ./theme.css` if the site's `_site.md` declares a `theme:` (it will refuse to build
without it, rather than quietly produce a site wearing only the baseline skin), and `--assets ./assets`
for the site's own media. `node engine/packages/build/cli.mjs` with no arguments prints the rest.

## The API

```js
import { buildSite, collectPages, stageSite } from '@tile/build';

// The IR walker: an IR directory → [{path, markdown}], sorted by path.
const pages = collectPages(irDir, { includePosts: false });

// Stage one site into the renderer. Returns the way out; ALWAYS call it.
const { restore } = await stageSite({ astroDir, pages, assetsDir, blogDir, pagetileDir, themeFile });
try { /* … */ } finally { await restore(); }

// Both of the above plus `astro build`, with the restore already wired.
const { code, outDir, pageCount } = await buildSite({
  irDir, engineDir, outDir,
  siteId: '', siteUrl: '', includePosts: false, themeFile, assetsDir,
});
```

`mkpages.mjs` is also a standalone CLI, and deliberately still the one it always was:

```
node packages/build/mkpages.mjs <ir-dir> [out.json] [--include-posts]
```

Its bytes are a contract, not an implementation detail — `collect-pages.test.mjs` holds them to a
fixture generated by the pre-move original. Change the JSON shape and that test goes red, which is
the point: something outside this repo reads it.

### The mapping, and why each rule is there

| IR | page path | route |
| --- | --- | --- |
| `home.md` | `home` | `/` |
| `about.md` | `about` | `/about/` |
| `legal/terms.md` | `legal/terms` | `/legal/terms/` |
| `zh-tw/home.md` | `zh-tw` | `/zh-tw/` |
| `posts/*.md` | — | staged into `blog/`, not `content/` |
| `_theme.md` | — | it is the theme SOURCE; it compiles to `theme.css` |
| `_site.md` | `_site` | not a route — the renderer reads it as config |

A locale home COLLAPSES: `zh-tw/home.md` becomes the page path `zh-tw`, so the Chinese homepage is
`/zh-tw/` and not `/zh-tw/home/`. Preserving the nested name instead is a real, measured defect —
it is what made one site advertise the wrong `hreflang` for a year.

`posts/` (and `posts-*`) are the blog corpus, not pages. Copied into `content/` they each become a
stray top-level route.

## Three sanitisers, one rule

A page path is data right up until the moment it becomes a filename. Three implementations of this
existed before this package; here is where each stood.

| | sanitises | given |
| --- | --- | --- |
| the collector (`mkpages.mjs`) | **nothing** | — |
| the shell orchestrator (private, pre-move) | `p.path.split('/').map(s => s.replace(/[^\p{L}\p{N}_-]/gu,'-')).filter(Boolean)`, `segs.length ? segs.join('/') : 'home'` | a `site_pages.json` from the collector |
| the ejected builder (private, in progress) | the same expression, ending `.join('/') \|\| 'home'` | its own walk of `ir/` |

**Verdict: the two that sanitise are equivalent, and the third is not a gap.**

The two expressions differ only in how they spell "nothing left → `home`", and `filter(Boolean)`
makes those two spellings the same function: after the filter no segment is empty, so a non-empty
array can never `join('/')` to `''`. `stage.test.mjs` proves it over a corpus rather than asserting
it — both formulations are transcribed there verbatim and run side by side against every case.

The collector having no sanitiser is not the third behaviour, it is the absence of one, and it is
correct: the collector emits DATA (a JSON array that something else may store, diff, or hand back),
and a path is not yet a filename there. `content/legal/terms.md` is where it becomes one. So the
rule lives in `stage.mjs` alone, spelled as `safePagePath()`, and the canonical form is the shell
orchestrator's — the one that has been running in production.

What the rule does: each `/`-separated segment keeps Unicode letters, digits, `_` and `-`, and
everything else becomes `-`. Empty segments are dropped; a path that sanitises away to nothing
becomes `home`. Unicode letters are KEPT deliberately — CJK slugs are live URLs on real sites, and
an ASCII-only rule would rewrite a working address into a row of dashes. Path traversal cannot
survive: `../x` becomes `--/x`.

There is a second, smaller difference between the two pre-move implementations, and it is NOT
equivalent: how they find the theme's NAME. The shell reads the first page whose markdown carries a
`theme:` line and requires a bare word (`/^theme:\s*(\S+)\s*$/m`); the ejected builder reads only
`ir/_site.md`, accepts the rest of the line, and falls back to the name `site`. This package takes
the shell's, again as the production one — see `themeNameFromPages()`.

## What is deliberately NOT here

Everything after `astro build` is deployment. It belongs to whoever runs the deployment, it is not
in this repo, and its absence is not an oversight:

- **no upload** — nothing is published anywhere by anything here
- **no build stamp** — no provenance file recording which platform built what, when
- **no `_worker.js` emitter** — no edge worker forwarding API calls to a platform
- **no canonical-host rewriting** — the site's origin is whatever you pass as `--site-url`
- **no `_redirects` merging** — your `assets/_redirects` REPLACES the renderer's rather than merging
  with it. That is the right way round (they are your rules), but it means any aliases the renderer
  shipped stop existing unless you add them back.
- **no leak checks, no share-image generation, no change detection**

And one absence that is about you rather than about the renderer: **`siteId` defaults to empty.**
The renderer's layout emits its ask-me bubble — a script fetched from a platform, calling that
platform — only when a site id is set. A build that quietly kept phoning home would be a strange
thing to hand somebody who just left. Set it yourself if you know what you want it to reach.

## The renderer is borrowed, and it is given back

`packages/sitetile/astro` ships its own `content/`, `blog/`, `pagetile/` and `public/` as worked
examples. Building a site moves all four aside, writes the site's own material in their place, and
moves them back — on success, on a failed build, and on a throw. `blog/` and `pagetile/` are
EMPTIED even for a site that has neither, because otherwise the renderer's demo posts and demo book
build into your site, under your domain, with nothing saying so.

🩸 `stage.mjs`'s restore undoes only what a run actually did. The shell it came from armed its
restore as an EXIT trap before staging began and then removed `blog/` and `pagetile/`
unconditionally inside it — so an early exit three lines in (a `--blog dir not found`) deleted the
renderer's own copies with no stash to put back, and every build after it was quietly missing them.

## Tests

```
node --test packages/build/*.test.mjs      # from the repo root
```

They also run in `scripts/test.sh` with the rest of the suite, one file at a time.

🩸 **Not `node --test packages/build/`.** On Node 22 a positional argument to the test runner is a
file or a glob, never a directory to search: given a bare directory the runner resolves it the way
an import would. With a `main` in this package's manifest that resolved to `index.mjs`, which
contains no tests — so the command printed `# tests 1 / # pass 1 / # fail 0` having read none of the
suites beside it. Without a `main` it fails with `MODULE_NOT_FOUND`, which is at least loud. The
manifest therefore has no `main` (`exports` resolves `import '@tile/build'` identically), and
`manifest.test.mjs` fails if one comes back. Expand the glob, or `cd packages/build && npm test` —
with no positional at all the runner does search, from the working directory.

The end-to-end test builds the fixture site with the real renderer and needs its dependencies
(`cd packages/sitetile/astro && npm install`); it names itself as skipped when they are absent
rather than passing on a check that never ran.
